# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repo layout

This `frontend/` folder is the Angular 18 CH5 touchpanel UI (`cmpg-521-ui`) for a Crestron Masters teaching kit (JSON objects and file operations). It is one half of the repo:

- `../backend/` — SIMPL# Pro (.NET 8) control-system program (`ControlSystem.cs`, `Config/` for JSON room-config load/save and presets, `UI/UiHandler.*.cs` partials per contract area, `Devices/DeviceEmulator.cs`). `UI/Contract/*.g.cs` is generated by Contract Editor, so don't hand-edit it.
- `../contract/AppContract.cce` — Contract Editor source shared by both sides.
- `../config files/`, `../docs/` — sample room-config JSON/XML.
- `../instructor note/` — course material, not code.

## Commands

```bash
npm install
npm start               # ng serve --open (http://localhost:4200)
npm run watch           # ng build --watch, development config
npm test                # Karma + Jasmine
npx ng test --include src/app/app.component.spec.ts   # single spec file
npm run compile         # ng build + ch5-cli archive -> archive/cmpg-521-ui.ch5z
npm run deployt         # ch5-cli deploy to touchpanel (IP hard-coded in package.json)
npm run deployp         # ch5-cli deploy to control system (IP hard-coded in package.json)
npm run cresprep        # rewrites type="module" -> defer in dist index.html; run between build and build:archive if a panel shows blank
```

There is no lint script. `start`, `build` and `watch` all run `sync:contract` first through npm pre-hooks.

## Contract file handling

WebXPanel always fetches `<base>config/contract.cse2j`, and that path can't be configured. `tools/sync-contract.js` copies the single authored `src/config/*.cse2j` (currently `AppContract.cse2j`) to `src/config/contract.cse2j`, which is gitignored. `angular.json` ships only the generated copy. Keep exactly one authored `.cse2j` in `src/config`, because the script fails if it finds none or more than one. After you change the contract in Contract Editor, export it over `AppContract.cse2j`. The backend's generated `UI/Contract/*.g.cs` must be regenerated from the same `.cce`.

## Architecture

- **All signal I/O goes through `src/app/service/controller.service.ts`.** It defines the `Contract` map of signal-name strings (e.g. `Sources.Source[${i}].Name`, `System.aPreset[${i}].Press`). These names must exactly match the names in the contract, because the panel resolves them to joins through the contract file. The service subscribes via `CrComLib.subscribeState`, holds state in plain fields, and exposes an rxjs `Subject` per area (`sourcesChanged`, `displaysChanged`, `audioChanged`, `messageChanged`, …). Components subscribe to these Subjects and call service action methods. Components never call `CrComLib` directly.
- `CrComLib` is a global loaded as a script from `@crestron/ch5-crcomlib` (see `angular.json` `scripts`) and declared with `declare var CrComLib: any`. `helpers/CrComLibHelpers.ts` adds typings and extension methods.
- Signal conventions:
  - Momentary actions are 10 ms digital pulses (`pulseDigital`), and the control system reports toggled state back on a `_Fb` or `Muted` state.
  - Analog levels are 0–65535 on the wire and percent in the UI (`toAnalog` / `toPercent`).
  - `Sources.Select` / `Sources.Selected` are 1-based, and 0 means none.
  - List sizes are fixed constants (`SOURCE_COUNT`, `DISPLAY_COUNT`, `PRESET_COUNT`) that must match the contract.
- Presets: a tap sends `.Press` (recall), and a 3 s hold sends `.Hold` (store). The hold timing is done in `presets.component.ts`, not on the control system.
- `app.module.ts` bootstraps WebXPanel:
  - When it runs in a browser (`isActive`), connection params come from URL query parameters (`host`, `ipid`, `roomid`, `tokensource`, `tokenurl`, `authtoken`, matched case-insensitively). CIP connect and disconnect events drive `ControllerService.connectedChanged`.
  - The hard-coded `configuration` object and the default `authToken` are dev/lab values.
- The app is module-based (`AppModule`) but mixes in standalone components (`StartPageComponent`, `MessageBoxComponent`, and the feature components that `StartPageComponent` imports). Routing uses hash URLs with `initialNavigation: 'disabled'` and navigates manually.
- Icons are Font Awesome Pro 6 SVGs through `@fortawesome/angular-fontawesome`. The Pro registry token is in the user-level `~/.npmrc`, not in the repo, so any other machine that runs `npm install` needs it too. Angular 18 limits it to Font Awesome 6, not 7. Add new icons to `helpers/icons.ts`, import `FontAwesomeModule` in the component, and use `<fa-icon [icon]="icons.x">`. Don't add icon fonts back. Use relative `url()` paths in CSS: the VC-4 serves the app from a sub-path, so root-absolute `/assets/...` URLs return 404 there even though they work under `ng serve`.
- Global CSS is kept small on purpose. `styles.scss` imports only the Bootstrap SCSS partials in use, and the 2 MB CH5 theme is not loaded, so `<ch5-*>` components will be unstyled. Add a Bootstrap partial there if you start using another Bootstrap component.
- Under `ng serve` there is no control system, so signal feedback is inert. It is still useful for layout and component work.
